## 对话中的需求与交付（按时间顺序，1.1.1 起为直接记录）

1. **图片缓存占用 + 清理缓存**
   用户要求（要点）：「新增图片功能后图片都会缓存到本机，长期使用占用很大…在设置中再增加一个清理本软件缓存数据功能，位置加在设置的『对话与用量』下方，可清理的具体缓存数据你来决定，完成任务交付 IPA」。
   交付（1.1.1）：新增 `AppCache` 缓存统计与清理（已失效图片、临时文件、网络缓存）；设置「数据」区新增「清理缓存」入口。

2. **优化输出卡顿、后台停止生成、token 统计**
   用户要求（要点）：「模型输出时『已深度思考』字体上下跳动、持续输出时整个软件卡顿、上下滑动卡顿；应用在后台时模型停止回复；token 计算无效；用 GitHub 的 Xcode 验证后交付 IPA」。
   交付（1.1.2）：去掉隐式动画消除跳动；流式增量缓冲（定频写 UI）；申请后台任务保证后台继续生成；`usage` 解析容错 + 本地 token 估算兜底。

3. **彻底解决展开输出后滑动卡顿**
   用户要求（要点）：「模型输出时展开输出内容后上下滑动仍非常卡顿，彻底解决，必要时可重构对话页面」。
   交付（1.1.3）：正文/思考分块渲染（已定型块整块复用排版），Markdown 解析结果缓存。

4. **对话页整体重构（弹窗式内容展示）**
   用户要求（要点）：「输出期间整个规划页面与左侧菜单栏都很卡顿；把对话页逻辑完全重构，输出内容改成点击弹窗显示，并彻底解决卡顿」。
   交付（1.2.0）：`StreamingText` 作为独立可观察缓冲，生成期间只有正在输出的消息视图刷新；过程/思考折叠为一行，点击弹出 `ProcessSheet`。

5. **标题栏、侧栏小标题、删除提问连带删除回复**
   用户要求（要点）：「对话页上方标题背景下滑时不要透明；删除左侧菜单栏的『对话记录』小标题；删除我发送的对话记录时把对应模型回复一并删除」。
   交付（1.2.1）：标题栏滚动保持不透明；移除分组小标题；删除用户消息时连带删除其后续的非用户消息（含工具结果）。

6. **侧栏长按样式、删除动画、Skill 功能**
   用户要求（要点）：「长按对话记录时背景改为不透明、背景边框改圆角；删除对话记录不会立即消失且与空状态图标重合，优化删除逻辑与动画；新增 Skill 功能（参考社区功能），可自行添加 Skill，并判断技能与智能体调用工具是否重合，若不重合则加上该能力」。
   交付（1.2.2）：侧栏行底色改为不透明 `rowSelected` + 圆角；去掉列表整体动画使删除即时移除；技能系统（技能库 + 自建/编辑/删除/启停 + `skill` 工具），技能规定做法、工具负责执行，二者不重合。

7. **技能编辑崩溃修复**
   由测试发现：技能编辑保存前后的进程异常退出（嵌套 sheet + 键盘 + TextEditor 组合不稳定）。
   交付（1.2.3）：编辑改为页内推入 `SkillEditorPage`，`TextEditor` 换成多行 `TextField`。

8. **「装了最新 73 版但和上一版一模一样」的排查**
   用户要求（要点）：「已安装最新 73 版本，但和上个版本一模一样，排查问题并重新交付下载链接」。
   排查结论：Release 里的 build 73 包本身完整（sha256 一致、二进制含技能等全部新功能）；它与上一版 build 70 的差异只有技能编辑器的内部实现，界面几乎一致；同时此前所有下载文件名都叫 `DSH-iOS-unsigned.ipa`、应用内也看不到版本号，无法分辨装的是哪一版。
   交付（1.2.4）：① 侧栏底部「设置」行右侧显示 `V<版本> (<构建号>)`；② 发布资产改为唯一命名 `DSH-iOS-<版本>-build<构建号>.ipa`，Release 标题同样带版本号。

9. **冷启动图标跳动 / 长按直角 / 技能开关与左滑 / 新增「查看画面」与文件 IDE**
   用户要求（要点）：「软件无后台刚打开时左右上角的图标会跳动，要求固定首次打开也不跳动；长按对话记录后出现的背景不要有直角，需要圆角；
   把设置里的技能开关删除、只保留技能库中的开关并把它放到顶部；技能列表向左滑动后再向右滑动会出现直角 UI 问题，
   修复并把左滑出现的删除背景色改为红色；新增让智能体具有 OCR 视觉效果、能主动查看例如浏览器内容的能力；
   新增内置文件管理器与 IDE 功能、可以编写代码」。
   交付（1.3.0）：
   - 冷启动顶栏：RootView 在首帧稳定前屏蔽隐式动画（`hasSettled`），抽屉宽度启动时只算一次并固定，
     关闭状态下同时置空透明度——避免冷启动瞬间布局收敛表现为「图标跳动」或抽屉闪现；
   - 长按圆角：用户消息气泡补上 `contentShape(.contextMenuPreview, 圆角矩形)`，与 1.2.2 侧栏行的修法一致；
   - 技能开关：设置页删掉 Toggle（只保留技能库入口），技能库页把「允许智能体调用技能」放到最顶部；
   - 技能列表左滑：行背景改为自绘圆角卡片（`listRowBackground` + 圆角矩形 + 隐藏分隔线），
     删除按钮显式 `tint` 为红色（列表整体的品牌色 tint 会把破坏性按钮一起染蓝）；
   - 查看画面（OCR 视觉）：新增 `screenshot` 工具与 `ScreenVision`（截取 App 窗口或内置浏览器 WKWebView 画面，
     用 Vision 做中英文本地 OCR）；截图作为图片附在工具结果之后发给模型（视觉模型直接看画面、纯文本模型读 OCR 文本），
     对话「过程」弹窗里能看到截图；开关在「设置 → 智能体工具」，默认开启；
   - 文件管理器与 IDE：新增 `Features/Files`（FilesView：浏览/新建/重命名/删除/图片预览，CodeEditorPage：等宽字体代码编辑、
     离开自动保存）与 `WorkspaceStore`（根目录 `Documents/Workspace`，系统「文件」App 里同样可见）；
     配套智能体 `workspace` 工具（list / read / write / mkdir / delete，路径限制在工作区内，
     文件内容原样写入不做裁剪），模型写下的代码可直接用内置 IDE 打开继续编辑。
   - 首轮 CI（build 78）测试发现两处问题并在 build 80 修复：`workspace` 工具对越界路径的提示文案
     （应与「文件不存在」区分）、文件页 UI 测试里编辑器返回按钮的定位方式（原写法会误触根导航栏的「完成」）。

10. **技能页左滑样式 / 侧栏删除过渡 / 模型输出样式与滚动卡顿 / 完整 MCP 协议支持**
    用户要求（要点）：「技能页的删除按钮与卡片宽度不一致且有直角，修复过渡样式；点击删除对话记录后应立即删除，
    只剩一条时先让记录消失、再出现『还没有对话』和上方图标；对话页模型输出要按参考图显示（标识行 + 思考/过程折叠行在前）；
    输出完成后上下滑动仍有轻微卡顿，一并优化；新增完整的 MCP 协议支持」。
    交付（1.4.0）：
    - 技能页左滑：不再用系统 `List.swipeActions`（删除区比卡片高、卡片圆角外露直角），改为自绘
      `SwipeToDeleteRow`——删除背景与卡片同高、同圆角裁剪、固定红色，点删除立即移除；
    - 侧栏删除：`filtered.isEmpty` 时延后 0.4s 再淡入空状态，避免被删记录与长按菜单收起动画还没结束就叠上
      「还没有对话」和图标；
    - 对话页输出样式：助手消息新增「鲸鱼标识 + DeepSeek」标识行，思考过程行、过程摘要行移到正文之前，
      与参考实现（TraeCode）一致；
    - 滚动卡顿：入场动画改由「消息是否刚生成（6 秒内）」决定——滚动时 LazyVStack 回收重建的行不再重播动画；
      正文 / 代码分块不再逐块 `textSelection`（跨块选择本来无效，逐块选择交互还会拖慢长回复滚动），
      整段复制仍可用消息下方「复制」；
    - MCP：新增 `Sources/Core/MCP.swift` + `MCPStore.swift` + `Features/Settings/MCPSettingsView.swift`。
      协议侧：JSON-RPC 2.0 over Streamable HTTP，覆盖 initialize（协议版本协商）、`notifications/initialized`、
      `Mcp-Session-Id` 会话与 `MCP-Protocol-Version` 头、tools/list、tools/call、resources/list、resources/read、
      prompts/list、prompts/get；响应兼容普通 JSON 与 SSE（text/event-stream），工具结果里的图片/音频转成文字说明。
      产品侧：设置 → 智能体工具 → MCP 服务器，可添加多台服务器（名称 / 地址 / 请求头）、连接并刷新、
      查看工具清单与提示模板（可一键填入输入框）；已启用服务器的工具以 `mcp_<别名>_<工具名>` 下发给模型，
      调用时由本机代发到对应服务器（会话过期自动换新会话重试一次）。
      验证：把 `MCP.swift` 单独编译成命令行程序，对真实 MCP 服务器（mcp.deepwiki.com）跑通了
      握手 → tools/list → tools/call 全链路；这次验证还顺带发现并修掉了 `contains(\.required)`
      少了 `where:` 标签的编译错误（81 构建因此失败，82 修复后为交付版）。

11. **技能左滑删除体验问题 / 调研并新增更多智能体工具**
    用户要求（要点）：「技能库的左滑删除按钮背景色不对、太暗，按钮出现后又消失、无法点击；
    顺便看看 GitHub 上的智能体工具是否还有适合本软件的，能加就加，代码风格与现有源码保持一致」。
    排查结论：用户截图里的删除区是**系统 swipeActions** 的渲染色（偏暗、按钮不跟手），
    而 1.4.0 起已改为自绘删除区（CI 截图中为鲜红实底）；本轮在此基础上继续加固，并补齐更多工具。
    交付（1.5.0）：
    - 技能页左滑：删除区用固定鲜红实底 `DSHTheme.dangerSolid`（0xFF3B30，不随浅色/深色变化）、
      展开阈值放宽到 1/4 宽度并加入 `predictedEndTranslation` 惯性预测（快速轻扫也能滑开，不再闪一下就弹回）；
      展开时再压一层透明点击层，保证「点红色区域 = 删除」；
    - 新增长按菜单兜底：技能卡片长按可「编辑技能 / 删除」，个别机型手势不跟手时也能删；
    - 新增智能体工具 **`clipboard`**（读写系统剪贴板；读取时 iOS 会弹「允许粘贴」确认，属系统行为）；
    - 新增智能体工具 **`reminder`**（系统「提醒事项 / 日历」，本机 EventKit）：
      list_reminders / create_reminder / list_events / create_event，
      时间支持「2026-10-10 09:00」「2026/10/10 15:00」「2026年10月10日 15:00」「只给日期按 09:00」「只给时间按今天」等写法；
      Info.plist 补充提醒事项与日历的四个权限说明文案；
    - MCP 服务器页新增**推荐服务器一键添加**：GitHub 官方 MCP（https://api.githubcopilot.com/mcp/，
      自动用「代码托管」里已登录的 GitHub Token 填 Authorization 头）、DeepWiki、Context7
      （三者均为官方托管的远程服务器，免本地安装；后两个免鉴权，已实测握手与工具列表）。

12. **侧栏删最后一条对话的重叠显示 / 按模型上下文窗口自动压缩上下文**
    用户要求（要点）：「只有一个对话记录时，删除它，记录还没完全消失『还没有对话』和图标就出现了，
    造成标题与空状态重叠；要求记录完全消失后再显示。另外增加一个功能：根据官方模型自动压缩上下文」。
    排查结论：记录本身是立即从列表移除的，用户看到的重叠是**长按菜单收起时那段「浮动预览」**
    （会在原位置停留约半秒），而空状态在 0.4s 时就淡入了，于是两者叠在一起。
    交付（1.6.0）：
    - 侧栏：空状态延后到 **0.7s** 再淡入，覆盖菜单收起动画，记录完全消失后才出现图标与「还没有对话」；
    - 新增 `Sources/Core/ContextCompactor.swift`：`TokenEstimator`（中文 1 字 ≈ 1 token、其余 4 字符 ≈ 1 token，
      并计入工具调用与图片）+ `CompactionPlan` + 摘要提示词与注入文本；
      `DSHModel.contextWindow` 按模型区分（Flash / V4-Pro 128k，未知模型 64k）；
      用量达到窗口 **75%** 时触发压缩，保留最近约 35% 窗口的内容，且**保留段必须从用户消息开始**
      （避免把 assistant 的 tool_calls 与它的 tool 结果拆开导致接口配对失败）；
    - 摘要作为一条 `isContextSummary` 消息存回会话，发送时以 **system 提示**注入
      （「此前对话的压缩摘要」+ 不要凭空编造），聊天页显示成可展开的「已压缩的历史上下文」卡片；
    - 手动入口：顶栏「…」菜单 → 压缩上下文（**手动不要求达到 75% 阈值**，只要有两轮以上历史就压，

19. **空回复「本轮没有返回内容」/ token 用量过大**
    用户要求（要点）：「经测试两轮对话最后模型都输出本轮没有返回内容；token 用量比其他软件大太多，
    看看有没有什么项目关于节省 token 用量，并让本软件也省 token」。
    交付（2.3.0）：
    - 根因：每条历史工具结果（网页正文上限 12k 字符、截图等）都会在**每次请求**里整段重发，
      且一轮最多 6 次工具调用逐轮累加，两轮读几页就能到 4 万+ 输入 token；
      模型在工具轮用尽 / 空响应时界面只留一句「（本轮没有返回内容）」。
    - 省 token（对齐业界主流做法：工具结果清除 / 截断 / 语义压缩，参考 Anthropic「context engineering」
      与 LLMLingua、ACON 等方向的工程结论，本项目不做 token 级剪枝——它需要额外的小模型）：
      `ToolOutputAging` 把较早轮次的工具结果发送前只留开头 400 字摘要并丢弃截图（当前轮完整保留、
      界面显示不变）；网页正文截断 12k → 8k（头 5.5k + 尾 2k）；所有工具输出加 16k 字符兜底；
      自动压缩阈值 75% → 70%、保留 35% → 30%，触发判断与「上下文 %」都按老化后的发送量估算，
      摘要请求也按老化后的内容发送（压缩本身更便宜）；
    - 空回复「收尾救场」：最终助手消息一个字都没写出时，追加一条**临时**用户消息
      （不写入会话记录）并下发**零工具**再请求一次，逼出文字结论；只有连救场也失败才回落到
      原来的「（本轮没有返回内容…）」说明；`ChatEngine.request` 把流式/非流式请求逻辑抽成一个方法；
    - 单测：`ToolOutputAgingTests`。

## 需求侧规律（供后续迭代参考）

- 用户关注点优先级：**流畅度 > 界面细节体验 > 功能扩展**；每次交付都要求「未签名 IPA 下载链接」。
- 交付方式固定：推送到 `main` 后 CI 构建，Release 页面下载 `DSH-iOS-<版本>-build<构建号>.ipa` 后自签安装。
- 用户会在真机长时间实测并反馈具体场景（输出中滑动、后台生成、长按、删除等），修完需说明「装完如何验证」。
